The symptom

Sounds like the audio is underwater

Voice goes robotic and warbly, or drops into short frozen gaps. It's heaviest right after you go live and eases as the stream settles. At the desk on Wi-Fi it never happens — only on a real drive.

The cause

An OBS Media Source regression

Recent OBS builds — 31.1.x through 32.0.x — shipped a bug in the Media Source: when it pulls an SRT stream that arrives a little slower than real time, its FFmpeg demuxer lags and freezes the audio. A bonded cellular commute is exactly "slower than real time," and the bond is coldest and jitteriest right at the start — which is why it's worst in the first minutes.

The fix is to stop using the Media Source for ingest. A VLC Video Source demuxes with libVLC instead of OBS's FFmpeg, so it steps around the bug completely.

The fix

Swap ingest to a VLC Video Source

  1. Install VLC first

    The VLC Video Source only appears if VLC is installed on your OBS machine — 64-bit to match OBS. If the source type isn't in the list, that's why.

  2. Add the source, matching the old name

    Sources → + → VLC Video Source. Name it identically to your current Media Source so any filters and Streamer.bot commands that target it by name keep working.

  3. Add your SRT URL via the Playlist

    In the VLC source properties, add the URL under the Playlist (the ＋ under the list) — not an Input field like the old Media Source had. Paste the same srt://… URL you were using before.

  4. Set the playback options

    Turn Loop ON, set Playback behavior to "Always play even when not visible," Network Caching to 400 ms, and Audio Track to 1. Caching lower than ~300 ms tends to re-introduce stutter on a cold bond; 400 is a good floor.

  5. Delete the old Media Source

    Once the VLC source shows picture and sound, remove the old Media Source so OBS isn't holding two ingests. Re-check your audio mixer routing if you had the old one assigned to a track.

⚠️

If the VLC source is black

VLC 3.x may not honor the SRT streamid parameter Belabox uses for routing, which shows up as a black source with no feed. If that happens, the clean fallback is to roll OBS back to a pre-31.1 build and keep using the Media Source there — the bug simply doesn't exist on older OBS.

🔌

This won't fix hard dropouts

This swap fixes the continuous warble. If instead your audio cuts out completely in chunks, that's a different, field-side problem — usually the DJI mic receiver dropping off a shared USB 2.0 bus, or rk_iommu page faults from the hardware HEVC encoder under real load. Those live on the Rock 5A, upstream of OBS entirely, and are tracked separately.
